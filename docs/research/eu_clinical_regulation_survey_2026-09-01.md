## 3. 立てられる主張と、立てられない主張

### 3.1 立てられる — EMA §6.6（原文確認済み）

EMA/INS/GCP/112288/2023 の 22 ページ、§6.6「データの管理」。
**PDF を落として全文検索で確認した。**"ledger" は文書中に 1 箇所だけ存在する。

> The sponsor should not have exclusive control of the data entered in a computerised
> system at any point in time. All data held by the sponsor that has been generated in a
> clinical trial should be verifiable to a copy of these data that is not held (or that
> has not been held) by the sponsor.
>
> [...]
>
> Instead of a system maintained by an independent service provider, the sponsor may take
> other adequate technical measures that preclude sole control. E.g. **the verifiability
> of data (transactions) by an independent (distributed) tamper-proof ledger may provide
> comparable security** to a system maintained by an independent service provider.
> **This should be justified and documented.**

**勝ち方の形を正確に。**

| | |
|---|---|
| 台帳が果たす役割 | 「依頼者による排他的管理の排除」＝**独立性**の代替 |
| 果たさない役割 | 完全性そのものの代替 |
| 付いてくる義務 | 「正当化され、文書化されること」 |
| 商業的な意味 | **許可**であって**需要**ではない。防御に使え、需要の根拠に使うな |

しかもこれは、より簡単で既に標準の経路（独立したサービス提供者を使い、治験責任医師に
認証済み複製を渡す）の**代替案**として書かれている。

### 3.2 立てられる — その他

| 掛かり | 出典 | なぜ効くか |
|---|---|---|
| 治験マスターファイルの変更追跡可能性 | **CTR 第58条**（拘束力のある法律） | この積み上げで唯一の**法定**改竄検知義務。25 年続く。大半の eTMF ベンダーより長い |

### 3.4 売ってはいけない機能

| 売れない | 理由 |
|---|---|
| 監査証跡の代替 | §6.2.1 は証跡が**システム内部**に保存され、人間可読、稼働中のシステムでデータ項目単位に可視、動的ファイルとして書出可能、旧値・新値・利用者・役割・組織・時刻・理由を持つことを要求。ハッシュはどれも持たない |
| レビュー作業の削減 | §6.2.2 が求めるのは**人間の、リスク準拠の、文書化された**活動。査察指摘は「ハッシュが無い」ではなく「レビュー記録が無い」 |
| 検証負担の軽減 | 証明の道具それ自体が適用対象の計算機システムになり、附属書 2・3・4 を満たす必要がある。**規制対応の総量はまず増える** |
| 保存義務の充足 | 第58条は**内容**を 25 年保存し完全かつ判読可能であることを要求。§6.12 は動的データの静的書出を拒否 |
| 電子署名 | §4.8 は EU 施設・開放系について **eIDAS 適合**を要求。ウォレット署名は既定では該当しない |

そして最も鋭い指摘：

> **固定は、固定した時点より前について何も証明しない。** GCP のデータ完全性の失敗は、
> 観察と最初の恒久記録の間の隙間で起きる —— 捏造された原資料、遡って入力された記録、
> 取り違えられた操作者。§4.4 の「**最初に得られる恒久データ**」こそ当局が見る場所である。
> 何段も下流の派生物を固定するのは、見かけより弱い主張であり、経験のある査察官は
> まさにこれを訊く。**固定点は装置の出力に物理的に可能な限り近く設計せよ。**

**証明の原始的部品はタダになった。** Intel Trust Authority は主要クラウドで無償、
H100 の証明も一般提供。NVIDIA NRAS はハードウェアに付属。
「この計算が改変されずに走ったことを証明します」だけを核にする会社は、無料の部品の転売になる。

**時計は動いている。** Seqera は 2026-04-30 に GxP 対応版を出した。GAMP5 第2版の文書一式、
21 CFR Part 11 / Annex 11 に沿った変更追跡、Nextflow 25.04 の lineage で全ファイル・
全タスクに固有 ID と来歴 JSON。**狙っていた内容の 8 割。**欠けているのは暗号だけで、
そこを埋めるのに 2 四半期あれば足りる。空き水域は **12〜18 か月**。

### 6.3 当局が、自動化しようとしている作業の範囲を自ら狭めている

MHRA の逐語：

### 6.12 申請書の第一段落が答えなければならない問い

調査エージェントが最後に置いた問いを、そのまま引く。

> **`sha256sum` ＋ RFC 3161 の時刻認証 ＋ RO-Crate が既にやらないことを、これは何をするのか。**
> 顧客の側の専門家合意文書（2025）が「ハッシュで足りる」と自分で書いており、
> その規制当局が一度としてそれ以上を求めたことがない相手に対して。

### 6.13 この問いへの答え（現時点での最良）

**答えは「記録」ではなく「判定」である。**

`sha256sum` はファイルが変わっていないことを言う。言わないことが三つある。

```
1. そもそも再実行できるのか
     → codescan の env_capture_class A/B/C は、宣言された依存の
       固定の強さを 格付け する。ハッシュは格付けをしない

2. 比較する相手が存在するのか
     → Tier-2 の comparison_verdict は no_target_declared を
       完全な結果として報告する。ハッシュは「対象がない」を言えない

3. 誰が判定したのか
     → Tier-2 は第三者が実際に再実行する。
       ハッシュは自己申告のままでも成立してしまう
```

つまり売っているのは改竄検知ではなく、
**「この解析は再実行できるか、そして一致したか」についての、格付けされた第三者の判定**である。

そしてこれは §6.4 の「買い手の側が違う」問題にも効く。判定は品質保証部門が買うものであり、
記録基盤は情報システム部門が買うものである。

## 8.5 健康データ保護 — 設計を決める制約

### 8.5.1 EDPB ブロックチェーン指針 02/2025 が **確定版 v2.0（2026-07-07）**になった

CNIL 2018 のメモはこれに置き換わり、**明確に厳しくなった**。この一件だけで実装方針が決まる。

| 条項 | 内容 | 設計への帰結 |
|---|---|---|
| **§104** | 個人データを「平文・暗号化・**ハッシュ**」のいずれの形でもチェーンに載せることは**推奨されない**。オフチェーンに置け | 「ハッシュだけ載せるから個人データではない」という定番の説明は、**確定版の本文に正面から否定されている** |
| **§52** | **ハッシュもまた個人データとみなされる。**「塩なし・鍵なしのハッシュは、一般に十分とみなされるべきでない」 | **CNIL 2018 の許容を反転させた。**無加工の SHA-256 で同意記録を固定するのが、最も指摘を受けやすい形 |
| **§53–54** | オンチェーンに置いてよいのは「**存在証明**として機能する形」——ポインタ、**暗号学的コミットメント**、鍵付きハッシュ。検証用データはオフチェーン。§53 は**完全秘匿コミットメント**を選好 | 規制当局が名指しで選好している基本部品が、相互証明が元々必要とするものと**一致している** |
| **§50** | 「技術的に不可能であることは、不遵守の正当化に使えない」 | 不変性は盾にならない |
| **§40** | 「**許可型チェーンを選好すべき**」。非許可型には文書化された正当化が要る | Wüst–Gervais の判定図の終端（許可型）と一致 |
| **§13** | 「**単一の主体**が生成し管理するチェーンは、本指針の一部の適用対象外」 | 単一運用者の追記記録は、多者チェーンより露出が明確に小さい |
| **勧告 9** | 当事者間の取引の個人データを削除できない構成では、**同意を法的根拠に使うべきでない** | **同意台帳は、この指針が名指しで警告している型そのもの** |
| **勧告 11** | 保存期間を保証する技術的解がないなら「個人データをチェーンに一切載せるな」 | — |

スペインのデータ保護当局（AEPD）の実証は、オンチェーンの削除を**検証者多数決によるハードフォーク**で実装している。**規制当局はチェーンを書き換え可能なものとして扱っている。**不変性は、盾ではなく、正当化を求められる設計判断である。

### 8.5.2 相互証明の売り文句に、直接刺さる二つ

**(1)「我々はデータを見ない」は、責任を免れさせない。**

> ガイドライン 1/2026 第135項 — 事業者は「**個人データを一切処理していなくても**、あるいは仮名化データのみを処理していても」管理者になりうる。
> ブロックチェーン指針 §§38–42 — 役割は**統治の仕組み**で決まる。ネットワークを運用し規則を定めるなら、管理者、あるいは全顧客との共同管理者になると想定せよ。

**選択的開示は、法的責任の遮蔽にはならない。**商業上の相手方に対する開示制御としては有効だが、それを「だから我々は処理者だ」という主張に使ってはいけない。

**(2) ゲノムデータは匿名と主張できない。**

CJEU の C-413/23 P（2025-09-04）は仮名化について相対説を確認したが、ゲノムには効かない。

- ガイドライン 1/2026 第165項: 遺伝的プロファイルは「**既定で個人データ**であり、匿名とみなせるのは例外的な場合のみ」
- 同 第167項: リスクは**血縁者にも、恒久的に**及ぶ
- ガイドライン 02/2026: 「記録の単離なし・連結なし・推論なし」を要求 —— 遺伝子型は構造上、単離する
- **CNIL は、より弱いデータで同種の主張をした IQVIA に €5,000,000 の制裁（2026-05-26）**

## 8.6 TEE（ハードウェア証明）— 判定

**一行の結論。** 半導体は使える。標準は半分できている。**安全性の履歴は宣伝より悪く、
この 12 か月で明確に悪化した。**BSI 以外どの規制当局も証拠として受け入れていない。
ゲノム分野は試作しかない。**作るべきは証明層ではなく結合層であり、
物理的攻撃者への耐性は決して主張してはならない。**

### 8.6.1 何を使えるか

| 技術 | 2026 年の状態 | 判断 |
|---|---|---|
| **Intel TDX** | 一般提供。Azure / GCP。処理量の低下 10% 未満 | **可**。最も配備されている |
| **Intel SGX（サーバ）** | **Azure の製品一覧から削除された** | **使うな** |
| **AMD SEV-SNP** | 一般提供。平均 13% の低下 | **可**。ただし 8.6.2 を見よ |
| **Arm CCA** | **使える半導体がない**。仕様は beta | **2027 年より前は計画に入れるな** |
| **NVIDIA CC**（H100 / Blackwell） | 一般提供。低下 4〜8% | 可 |
| 信頼できる I/O（PCI/TSM） | **第 1 段階のみ。`.bind` が無い** | 機密 GPU は今も CPU-TEE ＋ GPU-TEE ＋ 中継バッファ |

### 8.6.2 破られた履歴 — ここが判定を決める

| 時期 | 攻撃 | 破るもの | 費用 |
|---|---|---|---|
| 2024 | **Heckler**（USENIX Sec'24） | **TDX ＋ SGX ＋ SEV-SNP** | ソフトウェアのみ |
| 2025-05 | **BadRAM** | SEV-SNP、SGX | **$10 未満** |
| 2025-09 | **Battering RAM** | Scalable SGX、SEV-SNP の**証明の迂回**。起動時の信頼検査を全て通過 | **$50 未満** |
| 2025-10 | **WireTap** | サーバ SGX。**Quoting Enclave の ECDSA 鍵を抽出し、Intel 自身の検証ライブラリを通る quote を偽造** | **$1,000 未満** |
| 2025-10 | **TEE.fail** | **Intel TDX ＋ SGX、SEV-SNP、NVIDIA CC**。Intel の Provisioning Certification Enclave から鍵を抽出。著者いわく「**GPU を一台も持っていないのに、他人の装置の NVIDIA の証明を借りられる**」 | **$1,000 未満、鞄に収まる** |
| **2026-05** | **Insecure Despite Proven Updated** | **SEV-SNP（Milan）。root VCEK seed を抽出 → 任意のファームウェア版について有効な証明報告を偽造** | **ソフトウェアのみ。物理アクセス不要** |
| 2026-06/08 | OTRO、SparSEEty | **Intel TDX**。本番 TDX 上で入力の復元、BLEU > 0.95 | ソフトウェア |

AMD SEV の脆弱性報告は 2024〜2026 年 8 月で **19 件**、頻度は落ちていない。

**主張できる範囲。**

| 相手 | 判定 |
|---|---|
| (a) 遠隔のソフトウェア攻撃者 | **主張できる。**TDX と SEV-SNP は概ね持ちこたえている |
| (b) 悪意あるクラウド運用者 | **これは TEE の売り文句そのものだが、繰り返しソフトウェアで破られている。**2026-05 の VCEK seed 抽出は物理アクセスなしで証明を偽造する |
| (c) 物理アクセスを持つ攻撃者 | **主張は存在しない。**Intel も AMD も、interposer 攻撃は**対象外であり、緩和の予定はない**と明言。残存リスクではなく、**除外された脅威** |

> **相続する一文。** $1,000 と一度の物理アクセスがあれば、証明用の署名鍵を抽出でき、
> 以後、触れたことのない機械についても証明を偽造できる。
> つまり「**これは TEE の中で走った**」は「**有効な鍵を持つ誰かが、TEE の中で走ったと述べた**」に変わる。
> 規制上の証拠としては別の文であり、真なのは後者だけである。

### 8.6.3 規制上の受け入れ

| 当局 | 証拠として受け入れるか |
|---|---|
| **BSI C5:2026（独）** | **はい —— 唯一。**OPS-32 / OPS-33。**適用は 2027-06-01 から**。ただし「提供している場合は」の条件付き |
| NIST CMVP / FIPS 140-3 | **いいえ。**NVIDIA H100 の認証 #5446 は実在するが、証明用 ECDSA は「**Non-Approved, No Security Claimed**」 |
| Common Criteria | **いいえ。**認証済み・保管分 8,466 件に **Intel 0 件、AMD 0 件** |
| eIDAS | **構造的にいいえ。**推定力は**適格トラストサービス提供者の封印**に付く |
| FDA / EMA / Annex 11 / GAMP 5 / PIC/S / MHRA | **沈黙** |
| EDPB / GDPR | **沈黙**。ただし Use Case 6 は「今後の技術的発展が措置を提供する可能性を排除しない」と扉を開けている。**英 ICO が最も近い** |
| **EHDS** | **沈黙**。「secure processing environment」48 回、trusted execution / encrypt / attestation **0 回**。**第73条(5) の技術実施法令を、委員会は 2027-03-26 までに採択せねばならない。まだ書かれていない** |
| スイス FDPIC | **沈黙**。技術的組織的措置の手引に TEE は 0 件、**準同型暗号に §5.7 を割いている** |

**この不一致が最も重要な発見である。** ゲノムを見た当局（NIST、スイス FDPIC、CNIL LINC、EDPB）は
そろって **準同型暗号と秘密計算**を名指しし、TEE を名指ししていない。**この問いに答えを用意する必要がある。
「TEE の方が速い」は答えにならない。**

**そしてスイスでは直接ぶつかる。SPHN は連合クエリ層を Tune Insight（準同型暗号 ＋ 秘密計算 ＋ k 匿名化）に
既に賭けている。**

### 8.6.4 ゲノムでの実例 — 存在しない

- **TDX のゲノム論文 0 本。SEV-SNP のゲノム論文 0 本。全ゲノム規模の TEE による変異検出・アライメントの論文 0 本。**
- SECRET-GWAS（*Nature Comp Sci*, 2025）は 100 万人 × 400 万 SNP を謳うが、**コホートは 1000 Genomes からの増幅**、つまり合成規模。SGX 実装
- **Decentriq**（チューリッヒ）は 2023 年 1 月に SGX → SEV-SNP へ移行。実在の医療顧客あり（iCARE4CVD, 100 万人超）。**ゲノムは 0 件。**2022 年のシリーズ A のまま、2026 年の露出は広告技術が中心
- 国家事業 6 件すべて TEE なし。**SPHN / BioMedIT は VLAN 分離 ＋ 二要素認証**で、公開資料に TEE の言及なし

**唯一の本番の存在証明**は **Edgeless Systems × gematik ePA** —— ドイツの国民電子カルテ、Intel の機密計算、
最大 5,000 万人規模、2025-10-01 から医療機関に義務化。**駆動したのは規制上の運用者排除
（Betreiberausschluss）**。ゲノムデータは扱っていない。**これが論法の型になる。**

### 8.6.5 作るな / 作れ

**作るな（既に在る）。** 証明の生成、quote の検証、多者ポリシー。
Google **Confidential Space**（2023 年から一般提供）は、データ提供者・処理系の作者・運用者を
**相互に信頼しない主体として設計し、各当事者が自分のポリシーで自分の鍵の解放を制御する**。
Intel Trust Authority と NVIDIA NRAS は無償。**証明サービスを作ってはいけない。**

**作れ（本当に存在しない）。** **TEE の証明を、ワークフロー水準の来歴記録に結び付けるものが無い。**

| 対象 | 現状 |
|---|---|
| RO-Crate 1.3 | 完全性を**対象外**と明記。**署名の課題は 2023-12-18 から未解決、提案は 4 件とも放棄** |
| Workflow Run RO-Crate | **リリースは 0.5.0（2024-06）の 1 本のみ**。参照実装はいまだ 0.1 を出力 |
| IEEE 2791 BioCompute | **署名の欄が無い**。「進行中の事業なし」。**FDA が受理を表明したことは一度もない** |
| arXiv `"workflow provenance" AND attestation` | **0 本** |
| GitHub `in-toto ro-crate` | **0 件** |

接続部品はどれも小さく、規格の側に受け皿がある ——
**in-toto SCAI v0.3**（「Intel SGX ハードウェア上のビルドの証明」という実例を既に同梱）、
**SLSA BuildEnv L3**（SEV-SNP または TDX を明示的に要求）、
**EAR / AR4SI** の判定交換、**SCITT レシート**（RFC 9943、2026-06）。

### 8.6.6 選択的開示について正直に

**ゲノムパイプライン全体に零知識証明を掛けるのは不可能であり、可能にもならない。**
30× の全ゲノムのアライメントは約 10¹⁴ 命令、証明対象に直すと約 10¹⁵ サイクル。
実測 1 MHz（32 コア）で**約 100 コア年**。10⁴〜10⁶ 倍足りず、改善速度は目に見えて鈍っている。

**安いのは二つ。TEE の quote に対する零知識証明**（Automata が Flashbots の下で本番稼働）と、
**測定値に対する Merkle 帰属の零知識証明** —— 10⁵〜10⁶ サイクル、ノート PC で数秒。
**そして TEE の測定値に対してこれをやる既製品は存在しない。**

### 8.6.7 決して主張してはいけないこと

- TEE の証明が**物理的に居合わせる攻撃者に耐える**こと（製造者自身が耐えないと明言）
- **FIPS 検証済み**であること（H100 の認証は証明用暗号について「No Security Claimed」）
- **いずれかの規制当局が証拠として受け入れている**こと（BSI C5 の 2027-06 以降を除く）
- 証明が**相互運用可能**であること（EAT を出力している製造者は存在しない）
- 最も誘惑的なもの —— **ハードウェア由来の記録がソフトウェアの署名記録より強い**こと。
  WireTap と TEE.fail 以降、TEE の quote は**抽出費用 $1,000 の鍵による署名済みの陳述**である

> プロトコルの価値は、ハードウェアが信頼できることではない。
> **その陳述を、検証可能にし、ワークフローに結び付け、数年後に異議申立て可能にすること**にある。

## 8.7 先行研究 — Synoptis の新規性はどこに残るか

### 8.7.1 優先権はこちらにある

> **「Synoptis: Mutual Attestation for Trustworthy MCP Agent Networks」**
> Hatakeyama、Zenodo **2026-03-22**、doi:10.5281/zenodo.19161453、OpenAlex 収録済み

最も近い先行研究（Sokolov）の**最初の登録は 2026 年 6 月**。**三か月早い。**

### 8.7.2 arXiv 2608.00801 の中身

**「Hardware-rooted attestation for AI-agent evidence: composing IETF RATS with action evidence packages」**
Anton Sokolov（単著、Tyche Institute、タリン）、arXiv:2608.00801v1、cs.CR、2026-08-01 投稿、9 ページ、
「Technical note」。IEEE へ投稿中。被引用 **0**。

**著者自身が新規性を限定している。**

> 「機構そのものは**意図的に新しくない**……ここで新しいのは**合成だけ**である —— 応用層の行動記録を
> RATS の Evidence に束ね、プラットフォームの判定とともに一つの二軸語彙へ解決すること」

**Synoptis と重なる部分:** 中核の動き。署名された追記専用のソフトウェア行動記録を、独立した
ハードウェア証明と合成し、非専門家が読める判定語彙に落とす。**「自己申告とハードウェア証明の合成」を
見出しに書くと、彼の抄録を言い直すことになる。**

**重ならない部分（Synoptis の大半）:**

| 論点 | 2608.00801 |
|---|---|
| 当事者 | **単一当事者。B が存在しない**。RATS の Verifier は評価パイプラインの役割であって、判断が記録に入る独立した相手ではない |
| 外部固定 | **無し**。透明性ログも、登録簿も、第三者が検証できる包含証明も無い。「追記専用」はローカルのハッシュ連鎖の意味 |
| 撤回・訂正 | **一言も扱っていない** |
| 選択的開示 | **無し** |
| 領域への束縛 | **無し** |
| 実装 | swtpm（**エミュレートされた TPM**）、開発機 1 台、合成 AEP。**公開リポジトリ無し**。TDX も SEV-SNP も動かしていない |

**読むべき一節がある。**非決定性について、束縛が commit するのは AEP の**出力ダイジェスト**であって
生成過程ではないため、「第三者が同じ入力でモデルを再実行して同じ出力を再現することはできない」。
再導出を回復するには復号パラメータと擬似乱数の種を測定に入れる必要があり、それでも並列化と
アクセラレータの縮約により浮動小数点が結合的でないため、固定された数値経路の上でしか成立しない。
**ゲノムパイプラインが当たるのと同じ壁を、彼が先に地図にしている。再現性の主張を書く前に読むこと。**

### 8.7.3 本当の脅威は Sokolov ではない — 四つの方が近い

| 先行 | 何が済んでいるか | 対応 |
|---|---|---|
| **SLSA Verification Summary Attestation**（`slsa.dev/verification_summary/v1`、SLSA v1.2、in-toto/DSSE） | **合成の脚が既に標準化され配備済み。**検証者が生産者の証跡をポリシーに照らして評価し、署名済み要約を出す。消費者はそれを**基の証跡の代わりに**使う —— 明示的に「全ての証跡へのアクセスを不要にするため」。`verifier` / `policy` / `inputAttestations` / `verificationResult` / `verifiedLevels` | **合成済み主張の形式を設計する前に読む。**ただし **VSA は検証者の独立性を要求していない**（8.7.5 参照） |
| **RFC 9943（SCITT）＋ RFC 9942（COSE Receipts）**、2026-06、Standards Track | **追記専用・第三者検証可能なログの脚が完成済み。**「監査人・査読者・保証人といった独立した第三者」を正当な Issuer として明記 | 唯一の穴: **成果物についての陳述**は扱うが、**陳述についての陳述**は扱わない |
| **Agentic Witnessing**（Rowstron、arXiv:2604.24203、2026-04） | **概念的に最大の衝突。**TEE 内に隔離した LLM 監査者が、**MCP 経由で**非公開データセットを検査し、二値の問いに答え、推論の軌跡をデータとハードウェア根拠に束ねた署名済みハッシュ連鎖を出す。**評価対象は 21 本の論文の公開コードの検証** | **論文再現性監査の用途と正面から重なる。**要精読 |
| **Halimi et al., PoPETs 2022(3):732–753** | **ゲノム領域で**「A が申告し、B が検証し、全面開示なしに」を既にやっている。ワークフロー来歴と再現性が動機 | 検証は暗号ではなく**統計的**で、署名記録は無い。**自領域で最も出やすい「もう誰かがやった」反論** |

### 8.7.4 二つの危険

**(1)「Mutual Attestation」という語は占有されている。**arXiv の該当 10 件すべてが
「**二つのエンクレーブが互いのコード測定値を検証する**」の意味（MAGE、Know Thy Neighbor、TeeMAF、
LIRA-V ほか）。**セキュリティの査読者は題名だけで別の棚に入れる。改名すること。**

**(2) 五次元の信頼スコアは攻撃されている。**Hu, Rong & Van Kleek, FAccT 2026（arXiv:2605.30169）が、
エージェントは「存在論的に解離しており」評判型の統治は「構造的に適用不能」と論じている。
**捨てるか、明示的に防御するか。**

### 8.7.5 残る新規性 — 狭いが実在する

**プロトコルではない。**脚はすべて既存: RATS（RFC 9334）、SLSA VSA、SCITT（RFC 9943/9942）、
選択的開示（SD-JWT、RFC 9901）。四脚の**合成**は誰も公表していないが、それは弱い主張である。

残るのは二つ。

```
(1) 検証者の独立性を、記録された 検査可能な性質 として持つこと
      「B は A によって著述・設定・制御されていない」を、
      配備の前提として 仮定する のではなく、証跡の中に 運ぶ 不変条件にする
      → SLSA VSA は 検証者の独立性を要求していない。ここが空いている

(2) 領域への束縛
      BioCompute Object（IEEE 2791）を暗号的に証明したものが存在しない。
      IEEE 2791 の「verification kit」も FDA の一致試験も 手続き的で手作業。
      SCITT の文書は 医療・臨床試験・ゲノムに一度も言及していない
```

抄録の書き出しの案（調査エージェントによる）:

> 「本稿は、生産者の自己申告によるパイプライン主張と、独立した検証者によるその評価とが、
> **検証者の独立性それ自体が検査可能な性質として保持された**単一の透明性登録済み陳述へ合成される
> プロファイルを提示し、規制下の臨床ゲノムパイプラインのために IEEE 2791 BioCompute Object に
> これを束縛する」

**正直な内訳: プロトコルは新規でない。独立性の不変条件は薄いが実在する。領域への束縛が本体である。**

### 8.7.6 独立に到達した三点が一致している

「行為者が自分の仕事を判定してはならない」という規則に、三つの独立した経路が到達している。

| 出所 | 表現 |
|---|---|
| KairosChain INV-5 | 判定する context は、それを判定するものを著述してはならない |
| **BSI C5:2026 OPS-33.01AC** | 提供者が自社サービスで検証し結果だけ返す構成は **weak**。証跡を渡し相手の環境で検証させる形のみ **very strong** |
| **本節 (1)** | 検証者の独立性を証跡の中に運ぶ |

**規則は既知で、それを「運ぶ」実装が無い。**これが新規性の置き場所である。

### 8.7.7 いま標準化が動いている（窓）

- **draft-ietf-rats-multi-verifier-00**（2026-05）—— 一つの Verifier の判定結果が次の Verifier の入力になる
  段階的検証を標準化
- **draft-nobuo-scitt-composite-evidence-verification-00**（2026-07）—— 陳述グラフ上の合成検証、
  可搬な証跡束、「プロファイルに必要な証跡だけを提供する」

**合成的な証明は、この一年で二つの作業部会が標準化しつつある。**SCITT のプロファイル草案は約 21 本あり、
数本は直近三週間のもの。**臨床試験プロファイルを出すなら、いまが窓である。**
